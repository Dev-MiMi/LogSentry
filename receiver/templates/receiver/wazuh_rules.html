WAZUH INTEGRATION

Rules and investigations

These rules become active when installed on your Wazuh manager.

In Wazuh Threat hunting, select wazuh-alerts-* and search rule.groups: logsentry. Set the time range to include when Wazuh processed the event.

Security findings: rule.groups: logsentry_security. Routine activity: rule.groups: logsentry AND rule.level: 3. Level 3 records are informational context, even though Wazuh stores them in its alerts index.

Useful columns: rule.description, rule.level, data.logsentry.collector_id, data.logsentry.source, data.logsentry.ssh.source_ip, data.logsentry.ssh.username, data.logsentry.record_id.

Set the Wazuh dashboard timezone to Africa/Lagos. LogSentry already displays Nigeria time.

Repeated-failure rules use Wazuh processing time. Offline deliveries may arrive together even if the events happened hours apart. Compare original times, collector identity and distinct event IDs. Findings are leads for investigation.

These pages show retained evidence and rule guidance. To confirm an alert, check Wazuh itself or use the exact alert verification command on a private copy of alerts.json. Export status alone does not prove alerting or dashboard indexing.

Detection is scoped to the same collector, source, host and IP. Success after failures also requires the same username. Unknown usernames and failed-password messages are not counted twice. Rules do not learn personal schedules, assume a trusted network, or infer a banking-app login from a notification.
